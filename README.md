# 엄마의 낭독 스튜디오

엄마가 쓴 글을 붙여넣으면 Google의 최신 TTS 모델(`gemini-3.8-flash-tts`, 2026-09-23 출시)로
읽어주는 가족 전용 웹앱입니다. 가족 구성원이 각자 자기 구글 계정으로 로그인하고, 각자의
생성 기록은 서로에게 절대 보이지 않습니다. 결제는 관리자(당신) 명의의 Google 계정 결제
수단 하나로만 청구됩니다.

## 요금

Google 공식 요금(2026-09-28 기준):

| | 텍스트 입력 | 오디오 출력 |
|---|---|---|
| `gemini-3.8-flash-tts` (기본, 연기력 좋음) | 100만 토큰당 $0.50 | 100만 토큰당 $9 |
| `gemini-3.8-flash-lite-tts` (저렴, 대량용) | 100만 토큰당 $0.50 | 100만 토큰당 $6 |

- **`gemini-3.8-flash-tts` 기준 1분 ≈ $0.0135 (약 19원), 1시간 통으로 들어도 약 1,150원**
- 2026-12-31까지 프로모션가, 2027-01-01부터 2배로 인상
- 더 저렴한 모델로 바꾸려면 `app/api/tts/route.js`의 `model` 값을 `gemini-3.8-flash-lite-tts`로

## 구조 — 알아두면 좋은 것들

- **상시 접속 가능한 웹사이트가 되려면 배포가 필요합니다.** 로컬(`npm run dev`)로 띄운 건
  당신 컴퓨터가 켜져 있고 그 명령을 실행 중일 때만 접속되는 임시 상태예요. 아래 "배포하기"를
  따라 Vercel에 올려야 실제 도메인이 생기고 상시 접속됩니다.
- **API 키는 서버에만 있고 브라우저로 절대 안 나갑니다.**
- **로그인 = 결제 허가가 아닙니다.** Google 로그인은 "이 사람이 누구인지"만 확인해줄 뿐,
  누구나 자기 구글 계정으로 로그인하게 두면 링크가 새어나갔을 때 모르는 사람이 당신 카드로
  마구 쓸 수 있어요. 그래서 `ALLOWED_EMAILS`에 적어둔 이메일만 로그인이 허용되도록
  화이트리스트를 걸어뒀습니다 — 이게 진짜 보안 장치입니다.
- **각자의 기록은 서버에 계정별로 완전히 분리 저장**됩니다 (같은 컴퓨터/브라우저를 같이 써도
  섞이지 않아요 — 로그인한 구글 계정 기준으로 분리되기 때문입니다).

## Vercel이 뭔가요?

Next.js(이 앱이 쓰는 프레임워크)를 만든 회사가 운영하는 무료 호스팅 서비스예요. GitHub
저장소를 연결하면 자동으로 빌드해서 `https://프로젝트이름.vercel.app` 같은 실제 도메인을
줍니다. 서버를 직접 관리할 필요가 없고, 이 정도 규모(가족 2~3명 사용)는 무료 요금제로
충분합니다. GitHub 계정으로 바로 가입할 수 있어요 (https://vercel.com → "Sign Up" →
"Continue with GitHub").

## 1단계 — Gemini API 키 (완료하셨죠)

이미 발급받고 결제까지 연결하셨으니 이 단계는 끝났습니다. `.env.local`의
`GEMINI_API_KEY`는 그대로 두면 됩니다 — 유료 전환해도 키는 안 바뀝니다.

## 2단계 — 구글 로그인 설정 (본인이 직접 해야 하는 부분)

1. https://console.cloud.google.com/apis/credentials 접속 (Gemini 키 만든 것과
   같은 프로젝트를 쓰거나, 새 프로젝트를 만들어도 됩니다 — 둘은 서로 무관해도 돼요)
2. 화면에 "OAuth 동의 화면(OAuth consent screen)" 설정이 먼저 필요하면 그것부터:
   User Type은 **"외부(External)"** 선택 → 앱 이름("엄마의 낭독 스튜디오" 등), 본인
   이메일만 입력하면 끝 (심사 필요 없음 — 테스트 사용자로 등록한 사람만 쓸 거라서요).
   "테스트 사용자"에 엄마 이메일 + 본인 이메일을 추가해두세요.
3. "사용자 인증 정보 만들기" → "OAuth 클라이언트 ID" → 애플리케이션 유형
   **"웹 애플리케이션"**
4. **승인된 리디렉션 URI**에 추가:
   - `http://localhost:3000/api/auth/callback/google` (로컬 테스트용)
   - 배포 후 생기는 실제 주소도 나중에 추가해야 해요 (예:
     `https://your-app.vercel.app/api/auth/callback/google`) — 4단계에서 다시 안내
5. 생성되면 **클라이언트 ID**와 **클라이언트 보안 비밀(secret)**이 나와요. 이 둘을
   `.env.local`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 붙여넣으세요.
6. `.env.local`의 `ALLOWED_EMAILS`에 **엄마 구글 이메일과 본인 구글 이메일**을 쉼표로
   구분해서 적으세요. 이 목록에 없는 이메일은 로그인 자체가 거부됩니다.

```
GOOGLE_CLIENT_ID=발급받은 클라이언트 ID
GOOGLE_CLIENT_SECRET=발급받은 시크릿
ALLOWED_EMAILS=mom@gmail.com,me@gmail.com
```

## 3단계 — 로컬에서 먼저 켜보기

```bash
cd geminiTTS
npm install
npm run dev
```

http://localhost:3000 접속 → "Google로 로그인" → 화이트리스트에 있는 계정으로 로그인 →
정상적으로 스튜디오 화면이 뜨면 성공입니다. (로컬에서는 `BLOB_READ_WRITE_TOKEN`이 없어도
자동으로 프로젝트 안 `.data/` 폴더에 기록이 저장돼요 — `.gitignore`에 이미 포함되어 있어
실수로 커밋되지 않습니다.)

## 4단계 — 배포하기 (Vercel)

1. 이 폴더를 GitHub에 올립니다 (private 저장소 추천).
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   ```
   그다음 GitHub에서 새 저장소를 만들고 안내에 따라 push하시면 됩니다 — 이 부분은 원하시면
   제가 명령어까지 같이 실행해드릴게요.
2. https://vercel.com → GitHub으로 로그인 → "Add New" → "Project" → 방금 만든 저장소 선택
3. **Storage 탭에서 Blob 스토어 하나 생성**해서 이 프로젝트에 연결하세요 (무료 등급으로
   충분). 연결하면 `BLOB_READ_WRITE_TOKEN`이 자동으로 환경변수에 채워집니다 — 이게 각자의
   기록을 영구 저장하는 곳이에요.
4. Environment Variables에 나머지 값 입력: `GEMINI_API_KEY`, `GOOGLE_CLIENT_ID`,
   `GOOGLE_CLIENT_SECRET`, `ALLOWED_EMAILS`, `NEXTAUTH_SECRET` (로컬 것과 같은 값이면 됨)
5. Deploy → 몇 분 뒤 `https://프로젝트이름.vercel.app` 링크가 생깁니다
6. **이 실제 주소로 두 가지를 더 해야 완성됩니다:**
   - Vercel 프로젝트 Environment Variables에 `NEXTAUTH_URL=https://프로젝트이름.vercel.app` 추가 후 재배포
   - Google Cloud Console의 OAuth 클라이언트로 돌아가서 승인된 리디렉션 URI에
     `https://프로젝트이름.vercel.app/api/auth/callback/google` 추가
7. 이제 그 링크를 엄마·본인 둘 다에게 보내면, 각자 자기 구글 계정으로 로그인해서
   씁니다. 화이트리스트에 없는 사람이 링크로 들어와도 로그인이 거부돼요.

## 사용법

### 두 가지 모드

- **한 목소리로**: 문단 하나, 목소리 하나. 가장 간단하고 빠릅니다.
- **여러 등장인물 (대본)**: 나레이터 + 여러 캐릭터가 섞인 장면용. `"이름: 대사"` 형식으로
  한 줄씩 씁니다. 이름 없이 그냥 쓴 줄은 전부 나레이션으로 읽혀요 — "나레이터:"를 따로
  붙일 필요 없이 지시문만 쓰면 됩니다. 한 캐릭터의 대사가 여러 줄이면 줄마다 이름을
  반복해서 적어주세요.
  ```
  밤안개가 골목 끝까지 자욱하게 내려앉았다.
  지우: 누구야. 거기 누구 있어?
  그림자가 천천히 다가왔다.
  민준: 나야, 놀라지 마.
  ```
  처음 등장하는 이름은 목소리를 자동으로 배정하고(캐스팅 카드에 자동 추가됨), 마음에
  안 들면 그 카드에서 바로 바꿔서 다시 생성하면 됩니다. 캐스팅은 계정별로 서버에
  저장되어 다음에 또 고를 필요 없습니다. **버튼 한 번 = 파일 하나** — 등장인물이 몇 명이든
  줄마다 파일이 쪼개져 나오지 않고 이어붙인 오디오 하나로 나갑니다.

  **기술적으로 알아두면 좋은 점**: Google의 멀티스피커 기능은 한 번의 호출에 최대 2명까지만
  지원합니다(공식 문서엔 안 나와있고 실제 테스트로 확인). 그래서 이 앱은 대본의 각 줄을
  개별적으로 생성한 뒤 서버에서 하나의 오디오 파일로 이어붙입니다 — **등장인물 수 제한은
  실질적으로 없습니다** (한 번에 대사 60줄, 총 4천자까지 — `app/api/tts/route.js`의
  `MAX_TURNS`/`MAX_CHARS_SCRIPT`에서 조절 가능).

### 목소리 고르기

- **핵심 30종**: 모든 언어에서 쓸 수 있는 기본 목소리 (Kore, Puck, Sulafat 등)
- **확장 라이브러리 (한국어 페르소나)**: Google의 확장 목소리 카탈로그에서 한국어(`ko-KR`)
  목소리만 불러온 것 — 나이·직업·지역 억양(서울/부산 등)까지 설정된 캐릭터 보이스가
  꽤 많습니다. "Storyteller & Narrator" 계열은 특히 낭독에 잘 맞아요.
- 드롭다운이 길어서 클릭 후 **목소리 이름을 타이핑하면 브라우저가 해당 글자로 바로
  점프**해줍니다.
- 이름 옆 "미리듣기"로 실제로 들어보고 고를 수 있어요 (이 미리듣기는 기록에 저장되지
  않는 짧은 테스트 재생입니다).

### 감정 태그

텍스트 입력창 아래 태그 버튼(한숨/웃음/헛기침/짧게 멈춤/길게 멈춤)을 누르면 커서
위치에 `<sigh>`, `<laugh>`, `<cough>`, `<short pause>`, `<long pause>` 가 삽입됩니다.
대사 중간 어디든 넣을 수 있고, 실제로 그 지점에서 한숨/웃음 등을 연기해줍니다.

### 내 목소리 디자인하기

탭 위쪽의 "내 목소리 디자인하기 (선택)" 카드를 펼치면, 기존 목소리 중에 마음에 드는 게
없을 때 원하는 목소리를 문장으로 설명해서 완전히 새로운 목소리를 만들 수 있습니다.
예: `"60대 후반의 다정한 할머니 목소리, 살짝 쉰 듯하고 느긋하게 말함"`. 만들면 그
자리에서 샘플을 들어볼 수 있고, 이후 다른 목소리들과 똑같이 드롭다운의 "내가 만든
목소리" 그룹에서 계속 골라 쓸 수 있습니다 (계정별로 저장되며, Gemini 쪽 Voice Design
기능 — `POST /v1beta/voices` — 을 사용합니다). 실제 목소리를 녹음해서 그대로 복제하는
기능은 아니고, 어디까지나 문장으로 설명하는 방식입니다.

### 사용법 다시 보기

화면 위쪽 계정 표시 옆 "사용법" 버튼을 누르면 지금 이 사용법 안내를 웹사이트
안에서 언제든 다시 볼 수 있습니다.

### 짧게 테스트 → 길게 최종본

미리듣기로 목소리 후보를 짧게 들어보고, 캐스팅을 확정한 다음 "여러 등장인물" 탭에
씬 전체를 쭉 붙여넣어 한 번에 긴 파일로 뽑으면 됩니다 — 이게 원래 의도한 흐름이에요.

## 아직 없는 것 (필요하면 추가 가능)

- **진짜 목소리 클로닝** (엄마 실제 목소리를 녹음해서 그 목소리 그대로 복제) — 위의
  "내 목소리 디자인하기"는 문장 설명으로 새 목소리를 만드는 기능이고, 실제 음성을
  녹음해서 복제하는 것과는 다릅니다. 본인 음성 샘플 제공과 동의 절차가 필요한 기능이라
  원하시면 별도로 설계
- 기록 삭제 버튼 (지금은 최근 30개까지 자동 보관, 넘치면 오래된 것부터 자동 삭제)
- 사용량/비용 대시보드 — Google Cloud Console의 Billing 리포트에서 확인
